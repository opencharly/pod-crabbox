# 2026.256.0645 — fix(plan): dereference the annotated coordinator tag — no "is not a commit!" warning

## Summary

The cold `check-crabbox-e2e-pod` build carries a **zero-warning-gate finding** emitted by this candy's coordinator clone step:

```
warning: refs/tags/v0.51.0 c38e894f9405881993c326762ff2979c5d84f9d2 is not a commit!
```

**Root cause (R1, measured — before/after in one container, below):** the upstream coordinator release tags are **annotated**. `git clone --depth 1 --branch <annotated-tag>` starts a shallow fetch **at the tag object**, so git registers the TAG OBJECT (not a commit) as the shallow boundary, prints the warning, and only then resolves the peeled commit. The clone SUCCEEDS — but every COLD build of this candy is a finding under a zero-warning gate.

**Fix:** fetch the pinned tag as a plain **ref** (a ref fetch is warn-free) and check out its peeled commit explicitly:

```sh
git init -q /opt/crabbox-coordinator
git -C /opt/crabbox-coordinator remote add origin https://github.com/openclaw/crabbox
git -C /opt/crabbox-coordinator fetch --depth 1 origin "refs/tags/${CRABBOX_COORDINATOR_TAG}:refs/tags/${CRABBOX_COORDINATOR_TAG}"
git -C /opt/crabbox-coordinator checkout --detach "refs/tags/${CRABBOX_COORDINATOR_TAG}^{}"
```

(the plan step is the same four commands in ONE `command:` chain)

* same object set, same `--depth 1`, same checked-out tree as the replaced clone;
* the **tag ref stays present**, so `git describe --tags` still reports `v0.51.0`;
* no suppression anywhere — no `2>/dev/null`, no `--quiet`, no log filter: the warning disappears because git no longer asks to shallow-fetch THROUGH a tag object.

Candy `version:` `2026.250.0200` → `2026.256.0641`. The skill entity's stale `Build` row (`check:node` — not a plan step) is corrected to the plan's real steps (R1 doc-vs-reality).

### Consumer impact — a repin is required (follow-on)
