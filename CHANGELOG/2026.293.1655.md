## Summary

Moves the `crabbox-coordinator` skill body out of `charly.yml` and beside the candy, and keeps the routing metadata
`pod-crabbox#11` added.

| | |
|---|---|
| skill node | `crabbox-coordinator`, **`family: crabbox`**, owner `crabbox-coordinator`, `category: images` |
| body | `.agents/skills/crabbox-coordinator/SKILL.md` |

| manifest gains | 5 lines: `category: images`, `triggers:`, and its three list items |

**The surviving `content:` block belongs to `crabbox-coordinator:` - the service node - not to `crabbox-coordinator-skill:`.** The skill node's entire `content:` is removed; the service node's is untouched, which is what `classify.py` reports as `skill-owned = 1 | other = 1`.

**This is not a pure deletion, and that is deliberate.** `pod-crabbox#11` added `category: images` and three `triggers:`
phrases to this node; this PR rebuilds that work rather than discarding it, because the triggers and the body live in the same
node and two PRs editing one `charly.yml` is how a conflict happens twice. **The five added lines are `category: images`, `triggers:` and its three list items** - no blank line among them, which an earlier draft of this body claimed and the validator correctly refused. Listed from `git diff` rather than described.

### The node `description:` is deleted too

`sdk/deploykit/skills_collect.go` reads `entry.Description = s.Description` **only** on its `sf == nil` branch — the transitional
in-line form — and `entry.Description = sf.Description` overwrites it unconditionally once a body file exists. So after this
migration the node field is unreachable dead duplication.
