# 2026.247.1016 — feat: pod-crabbox — the Crabbox coordinator service candy

## Summary

New standalone repo `opencharly/pod-crabbox` — the **Crabbox coordinator** candy
(`crabbox-coordinator:` entity, the Node.js/PostgreSQL runtime) plus its skill
entity, mirroring the pod-openclaw root-entity repo shape. Step 3 of the
100%-local Crabbox×OpenCharly integration (plan/crabbox-integration.md):

- Builds the coordinator from the pinned upstream tag (`v0.49.0`) in-image:
  `git clone` → `npm ci --include=dev` → `npm run build:node` →
  `npm prune --omit=dev` (the upstream `worker/Dockerfile.node` recipe incl.
  the noVNC vendor step; devDeps forced at build because the candy's
  `NODE_ENV=production` would drop esbuild — probe/RCA-verified).
- Runs it as a supervised service (priority 20, after the postgresql
  service's 10) on port 8080 with `/v1/health` + `/v1/ready` probes, backed
  by the opencharly `postgresql` candy (PostgreSQL 13+, pg-boss; schemas
  auto-created on startup).
- A start wrapper assembles `DATABASE_URL` from deploy-provided `POSTGRES_*`
  env (supervisord cannot expand variables) and waits (bounded `pg_isready`)
  for the database — live-bed RCA: without the wait the coordinator
  ECONNREFUSED-crash-looped; the dropped `port_relay`/`layer-socat` removed an
  EADDRINUSE clash with the relay on :8080.
- Auth is deploy-time: shared-token (`CRABBOX_SHARED_TOKEN` + `_OWNER`) for
  the fully-local mode; GitHub OAuth documented for production. No
  production-cloud cutover claims (upstream flags the Node runtime as newly
  shipped; exact-tag pin + in-beds proof + single replica).
