# 2026.309.1841 — fix(bed): derive the lease user's home from passwd, not a hardcoded path

Derives the lease login user's home from passwd instead of hardcoding `/home/crabbox`, so the bed's reset and its file-absence assertion can actually fail. One of three PRs closing `opencharly/pod-crabbox#5` (siblings: `pod-crabbox-systemd#5`, `pod-crabbox-nested#6`).

## Summary

The bed's absence step did:

```sh
rm -rf /home/crabbox/.ssh
```

```sh
test ! -e /home/crabbox/.ssh/authorized_keys
```

**Both were vacuous on this image.** The contract user is created by `candy/crabbox-guest/charly.yml` as:

```yaml
                  if [ -n "$existing" ]; then
                    usermod -l crabbox -s /bin/bash "$existing"
                  else
                    useradd -m -u 1000 -g 1000 -s /bin/bash crabbox
                  fi
```

On CachyOS uid 1000 already exists as `user`, so the **`usermod -l`** branch runs — and `usermod -l` renames the account **without moving its home**, which stays `/home/user`. So the reset removed nothing (the real file is `/home/user/.ssh/authorized_keys`), and `test ! -e /home/crabbox/.ssh/authorized_keys` was **trivially true because that path never exists**.

The bed still discriminated — a freshly generated key is refused over SSH — but it claimed a reset it did not perform, and one of its assertions could never fail. That is the same defect as `test -s` standing in for uniqueness: an assertion whose falsifying condition its path cannot express.

The fix derives the home once and asserts it is non-empty, so a missing user fails loudly rather than silently reverting to a vacuous check:

```yaml
                      # The contract user's home is the passwd entry's field, never a
                      # hardcoded /home/crabbox: this base adopts uid 1000 from the
                      # distro image (measured: crabbox's home is /home/user), so a
                      # hardcoded path would make the absence probe vacuous.
                      home="$(getent passwd crabbox | cut -d: -f6)"
                      test -n "$home" || { echo "FAIL: the lease user crabbox has no passwd home" >&2; exit 1; }
                      rm -rf "$home/.ssh"
```

and, further down the same step:

```yaml
                      test ! -e "$home/.ssh/authorized_keys"
```

`pod-crabbox-code`'s bed already derives the home; this brings the three sibling beds onto the same idiom rather than inventing a second one (R2).
