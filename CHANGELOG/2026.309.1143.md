# 2026.309.1143 — feat(bed): add the first disposable lease bed for pod-crabbox

## Summary

**Head `578dac6d6700e37c5598fa55a18d4fbfc7fc31d6` — 1 file, +141/−0.** Adds `check-pod-crabbox-lease`, the first `disposable: true` bed in `opencharly/pod-crabbox`.

Before this change the base lease image was verified only at the build boundary (`charly check box`), so the `/crabbox` contract every `pod-crabbox*` lease inherits — `sshd` on 2222, public-key auth as `crabbox`, passwordless sudo, the shared bootstrap consuming the read-only `/crabbox` inputs, and `/usr/local/libexec/crabbox/ready` exiting 0 — had never been exercised on a running lease. `origin/main` carried no disposable bed; this commit adds the first:

```
$ git show origin/main:charly.yml | grep -n "disposable: true"; echo "grep_rc=$?"
grep_rc=1
$ git show HEAD:charly.yml | grep -c "disposable: true"
1
```

The bed is the check system's three-step shape:

1. **ABSENCE** — reset the state, then prove the freshly generated key is refused and no `authorized_keys` exist. The refusal must be an authentication refusal; a venue that does not answer fails this step, so a broken endpoint cannot read as "nothing applied yet".
2. **PERFORM** — write `authorized_keys`, `lease.env` and `bootstrap.sh` temp + `mv` (the contract's own input protocol) and run the image's shared bootstrap.
3. **PRESENCE** — over the contract's own SSH path as `crabbox`: the key is accepted, `sudo -n true` succeeds, and the readiness hook exits 0.

**The containerd substrate leg is NOT claimed.** It was measured while authoring this bed: in the pinned toolchain a `pod:` deploy's authored `engine:` selector is dropped by the check-bed `config`/`start` path (`charly config` emits a podman quadlet), and `charly deploy add --engine` is an unknown flag. That gap is filed as opencharly/charly#1109. The bed therefore proves the image's own, engine-independent running contract on a disposable pod; the containerd lease leg remains opencharly/plugin-crabbox's `check-crabbox-containerd-e2e` bed.
