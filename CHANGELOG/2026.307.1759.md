1. **A1 / T3 / R5 — docs misstated the image's `user:`.** `charly.yml` sets `user: root`; `AGENTS.md` said `user: crabbox`. **The code was right, so the prose was corrected** (R4).

3. **A2 / R10 — the image build was never proven, and running it found a real defect.** This round supplies the build and the checks — and the check that had never executed was failing for a genuine reason.

### The defect the gate exposed

```
$ charly check box pod-crabbox            # before the fix
  FAIL  check the lease user is uid 1000, named crabbox, with bash  [crabbox-guest-user]  exit=1
8 steps: 4 passed, 1 failed, 3 skipped

$ podman run --rm --entrypoint /bin/sh ghcr.io/opencharly/pod-crabbox:2026.307.0955 -c 'getent passwd 1000'
user:x:1000:1000::/home/user:/bin/bash
$ ... -c 'getent passwd crabbox'
(empty)
```

**Mechanism:** the distro base creates a generic `user` at uid 1000, and the candy's creation step guarded on `if ! getent passwd 1000`. The guard was always false, so `crabbox` was never created. **Blast radius:** `ready.sh` asserts `getent passwd crabbox` on every lease and exits non-zero without it, so **every lease would have failed readiness** — not merely a red check. **Missed control:** the check existed and asserted exactly this, but had never run, because the CI build died in the base layer before reaching the candy. **Root fix:** guard on the contract **name** and adopt the existing uid-1000 account (`groupmod -n crabbox`, `usermod -l crabbox -s /bin/bash`), keeping a create-from-scratch arm for a base without uid 1000.
